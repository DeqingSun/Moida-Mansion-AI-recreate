# Unsplit electrode experiment — 2026-10-15

Production converter and working EDA project are unchanged.

## Reproduce

From the repository root, use a new temporary directory:

```sh
node 2_refine_routing/eda/experiments/unsplit.cjs pad /tmp/moida-unsplit-pad
node 2_refine_routing/eda/experiments/unsplit.cjs fill /tmp/moida-unsplit-fill
```

The generator uses the existing sample selection and replaces the split electrode
C00S253, which has one outer boundary and one hole. Other sample electrodes,
connectors and associated traces remain controls. It refuses to overwrite an
existing directory. These are experiments, not production export files; mapping
pad IDs are not rewritten for the legacy full-geometry importer.

Open the generated `.eprj3` with `eda/cli.py open`, open board
`f5ed743606c8c036`, and call `pcb_ManufactureData.getDxfFile` with
`[{layerId:1,mirror:false}]`. Inspect HATCH boundary-loop counts (DXF group 91),
not merely whether the file saved successfully.

## Native application results

Tested in the installed LCEDA Pro application; saved native document reports
editVersion 4.1.78.

| Representation | Native save | Top-layer DXF result |
| --- | --- | --- |
| One polygon pad with nested outer/hole contours | Succeeded; nested path retained | Electrode omitted. 51 single-loop hatches (48 connectors + 3 control electrodes); no two-loop hatch. |
| One board FILL per layer with outer/hole contours | Succeeded | Continuous electrode boundaries, but an extra solid outer-only hatch accompanies the two-loop hatch. 52 single-loop hatches + 1 two-loop hatch. |

The FILL API correctly returned the top and bottom nets as T-N042 and B-W008.
The extra outer-only hatch has the same outer geometry as the holed electrode;
it can obscure the hole. Removing the bottom FILL did not eliminate it. A fresh
project generated by this script reproduced the same result, ruling out leftover
objects from the initial experiment. No vertical partition boundary is needed
in the FILL representation, but the DXF is not yet verified as fabrication-safe.

## Conclusion

Unsplit net-bearing copper regions are a promising EDA representation, but these
tests do **not** establish a drop-in replacement for component pads or a reliable
EDA DXF manufacturing path. Routing behavior, connectivity/DRC and component
association still need validation. Keep the production exporter unchanged.

For a clean manufacturing DXF, direct export from the webpage geometry (preserving
outer and hole contours, and unioning same-layer/same-net copper as appropriate)
would avoid both pad partition seams and the observed native DXF duplicate hatch.
That is a proposed next step, not implemented by this experiment.
